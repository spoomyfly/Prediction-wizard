# Симулятор турниров

Веб-приложение, которое методом Монте-Карло (по умолчанию 10 000 прогонов) симулирует
оставшиеся матчи турнира и показывает вероятность итогового места каждой команды.

Стартовые турниры — еврокубки сезона 2026/27 (Лига чемпионов, Лига Европы, Лига конференций) и
The International 2026 по Dota 2, как пример турнира другого вида спорта.

## Стек

- Vue 3 + Vite + TypeScript, Composition API, `<script setup>`.
- Vue Router (`createWebHashHistory` — чтобы обновление страницы на GitHub Pages не давало 404).
- Pinia для состояния.
- Web Worker для самой симуляции, чтобы интерфейс не подвисал во время расчёта.
- Vitest для тестов движка.
- Без бэкенда: все данные — статические JSON в `public/data/<competitionId>/`.

## Запуск

```bash
npm install
npm run dev       # локальный сервер разработки
npm test          # тесты движка (vitest)
npm run build     # typecheck + сборка в dist/
npm run preview   # локальный просмотр собранной версии
```

## Деплой

`.github/workflows/deploy.yml` при пуше в `main` прогоняет `npm ci && npm test && npm run build`
и публикует `dist/` через `actions/upload-pages-artifact` + `actions/deploy-pages`. В настройках
репозитория GitHub Pages → Source должен быть выставлен на **GitHub Actions** (Settings → Pages).

## Архитектура

### Движок (`src/engine`) — чистый TypeScript, без зависимости от Vue

- `rng.ts` — детерминированный seedable PRNG (mulberry32) + Пуассон/нормальное распределение
  на его основе, чтобы результаты воспроизводились при одинаковом seed.
- `models/poisson.ts` — футбольная модель: `λ_дома = avg × attack_дома × defense_гостей ×
  √homeAdv`, `λ_гостей = avg × attack_гостей × defense_дома ÷ √homeAdv` (симметричный `√`-сплит,
  чтобы homeAdv двигал баланс дома/выезд, не утягивая суммарную результативность матча); счёт
  разыгрывается по Пуассону. Поправка Диксона–Коулза на низкие счета — опциональный флаг `rho`,
  по умолчанию выключен.
- `models/series.ts` — Dota 2: вероятность выигрыша карты по Эло (`p = 1 / (1 + 10^(-(Ra-Rb)/400))`),
  серии Bo1/Bo2/Bo3/Bo5 разыгрываются карта за картой (Bo2 может закончиться вничью).
- `strength.ts` — `resolveTeamStrengths(teams, params)`: Эло → атака/оборона с настраиваемым
  влиянием рейтинга и переопределениями по командам; используется и офлайн-генератором данных, и
  живой панелью на странице «Сила команд» (см. ниже), поэтому расчёт не может разойтись между
  ними.
- `formats/leaguePhase.ts` — единый этап лиги (как в еврокубках 2026/27): реализован полностью.
- `formats/swiss.ts`, `formats/doubleElim.ts` — **TODO**, только интерфейс и заглушка с описанием
  плана в комментариях (используются форматом The International).
- `tiebreakers.ts` — набор тай-брейков; конфиг турнира собирает из них нужный порядок.
- `simulate.ts` — оркестратор Монте-Карло: `simulate(config, teams, fixtures, results, n, options)`
  возвращает по каждой команде распределение мест, вероятность зон, ожидаемые очки и место.
  Уже сыгранные матчи (есть в `results`) не пересимулируются. В каждом прогоне к силе команд
  добавляется случайный шум σ из конфига (`noise.ts`), отражающий неопределённость оценки.

### Конфиг турнира (адаптер, `src/competitions`)

```ts
interface CompetitionConfig {
  id: string
  name: string
  sport: 'football' | 'dota2'
  format: FormatSpec          // 'league-phase' | 'swiss' | 'groups' | 'double-elim'
  matchModel: 'poisson-goals' | 'bo-series'
  tiebreakers: TiebreakerId[]
  zones: Zone[]
  modelDefaults: ModelDefaults
}
```

Все турниры регистрируются в `src/competitions/index.ts`. **Чтобы добавить турнир** (в том
числе другого вида спорта): создать новую папку `src/competitions/<id>/config.ts` и положить
данные в `public/data/<id>/{teams,fixtures,results,ratings}.json` — движок при этом не меняется.

### Панель «Сила команд» (`/:competitionId/strength`)

Для футбольных турниров — живые параметры модели, а не просто макет: влияние рейтинга, домашнее
преимущество, средняя результативность, шум σ, ρ Диксона–Коулза, а также рейтинг Эло (K, домашнее
преимущество в очках Эло, вес формы, буст K при смене тренера) и ручная корректировка по каждой
команде (переопределение базового Эло, ±%, тур смены тренера). Таблица атаки/обороны
пересчитывается мгновенно (чистая функция, без симуляции); полный прогон запускается
автоматически с debounce — 1k сразу, 10k после того как вы отпустили ползунок/убрали фокус с
поля — и обновляет вероятности на странице турнира.

Текущий Эло нигде не хранится — он выводится: `src/engine/elo.ts` прогоняет базовый рейтинг
команды через все сыгранные матчи заново при каждой загрузке (`replayElo`), так что повторно
применить один и тот же матч невозможно, а исправление старого результата само чинит всю цепочку
после него. Форма считается через декэй-среднее отклонений от ожиданий Эло (не через сырые
результаты — иначе она задваивала бы то, что уже учтено в рейтинге).

Состояние параметров хранится в Pinia + `localStorage`, отдельно по каждому турниру; кнопка
«Сбросить» возвращает к значениям из конфига. Для Dota 2 панель остаётся заглушкой — сначала
нужно реализовать сам формат (Swiss + плей-офф), иначе настраивать нечего. Подробности и то, что
ещё не реализовано (источники/веса, ротация в последнем туре, все параметры Dota) —
[`docs/strength-params.md`](docs/strength-params.md).

### Данные (`public/data/<competitionId>/`)

- `teams.json` — идентичность команды (id, название, страна, клубный коэффициент и т.д.).
- `ratings.json` — рейтинги (elo/attack/defense), источник и дата обновления.
- `fixtures.json` — календарь (id, тур, хозяева/гости).
- `results.json` — результаты уже сыгранных матчей (по `fixtureId`).

Загрузка идёт через `src/data/loadCompetitionData.ts` с лёгкой валидацией формы (обязательные
поля, типы) — при поломке источника приложение покажет понятную ошибку, а не упадёт молча.

`scripts/generate-seed-data.ts` (`npm run generate-seed-data`) генерирует эти файлы для всех
турниров из движка же (тот же `fixtureGenerator.ts` и модели матчей), с фиксированным seed —
воспроизводимо.

## ⚠️ Ограничения текущих данных

У этой сборки нет доступа ни к одному внешнему API/живому фиду данных, поэтому большая часть
составов/календаря/рейтингов — иллюстративные заглушки. Исключение — **Лига чемпионов 2026/27**:

- **Состав участников (36 клубов), календарь всех 8 туров и результаты 1-го тура
  (8-10 сентября 2026) — реальные.** Состав и 1-й тур сверены по совпадению итоговой таблицы
  после тура (16 команд с 3 очками, лидер ПСЖ с разницей +5). Календарь туров 2-8 (даты:
  13-14 окт, 20-21 окт, 3-4 ноя, 24-25 ноя, 8-9 дек, 19-20 янв, 27 янв) собран из нескольких
  независимых источников и структурно проверен кодом: все 144 матча, каждая из 36 команд
  встречается ровно 8 раз с 8 разными соперниками (без повторов), баланс 4 дома / 4 на
  выезде — как в официальном регламенте. Результаты туров 2-8 неизвестны (матчи ещё не
  сыграны), поэтому симулируются. См. `uclRealTeams`/`uclMatchday1` в
  `scripts/generate-seed-data.ts` и `scripts/data/ucl-2026-27-schedule.ts`.
- Календарь ЛЕ/ЛК — сгенерирован упрощённым круговым алгоритмом (каждая команда получает нужное
  число уникальных соперников), а не настоящей жеребьёвкой УЕФА по корзинам с учётом
  страны/коэффициента; состав участников ЛЕ/ЛК тоже правдоподобный, но не сверен с официальной
  жеребьёвкой 2026/27.
- Рейтинги силы команд (Эло/атака/оборона) везде, включая ЛЧ, подобраны вручную по общему
  впечатлению о силе клубов, не взяты из ClubElo/The Odds API/OpenDota.
- The International 2026: только состав команд и рейтинги + демо-фикстуры первого раунда
  Swiss-стадии с частично скрытыми результатами. Полная симуляция формата (Swiss + плей-офф на
  выбывание с двумя поражениями) не реализована — см. TODO в `engine/formats/swiss.ts` и
  `doubleElim.ts`. Страница турнира в этом случае показывает только «Силу команд».

Список реальных источников, которые стоит подключить вместо заглушек, и как их предполагается
использовать — в [`docs/strength-params.md`](docs/strength-params.md) и в `scripts/update-data.ts`.

## Автообновление данных

`scripts/update-data.ts` и `.github/workflows/update-data.yml` — заготовка ежедневного
обновления (cron 06:00 UTC): структура шагов (забрать результаты и рейтинги → сравнить с текущими
JSON → закоммитить при изменениях) готова, но сами запросы к источникам не реализованы
(нет доступа к API-ключам в этой сборке) — см. TODO в файле скрипта. Ключи API **не должны**
попадать во фронтенд — только в GitHub Secrets, используемые самим workflow.

## Ограничения модели

- Голы/карты считаются независимыми матч от матча — не учитываются усталость к концу турнира,
  травмы в моменте, «игра по счёту».
- Тай-брейки реализованы по цепочке критериев УЕФА для единого этапа лиги; для других форматов
  (Swiss/double-elim) не используются.
- Полная реализация Swiss и double-elimination — TODO (см. выше).

Подробное описание модели простым языком — на странице `/about` в самом приложении.

## Тесты

```bash
npm test
```

Покрытие движка: среднее числа голов ≈ λ (Пуассон), тай-брейки на вручную составленных кейсах,
детерминизм при одинаковом seed, сумма вероятностей мест каждой команды равна 1, и перфоманс-тест
(10 000 прогонов 36-командного этапа лиги быстрее 1 секунды).
