# Параметры силы команд (предложение, логика не реализована)

Страница «Сила команд» (`/:competitionId/strength`) сейчас — только макет: она показывает
текущие рейтинги из `ratings.json` и список отключённых контролов с пометкой «скоро». Ни один
из параметров ниже не подключён к движку симуляции (`src/engine`). Этот документ фиксирует,
как их предполагается реализовать, когда до этого дойдут руки.

## Зачем это нужно

Сейчас `attack`/`defense`/`elo` в `ratings.json` — статические числа. Модель силы должна уметь:

1. Комбинировать несколько источников рейтинга с весами.
2. Учитывать структурные факторы матча (своё поле, средняя результативность).
3. Отражать неопределённость (шум σ) и краткосрочные события (травмы, ротацию, смену состава).

## Глобальные параметры (футбол)

| Параметр | Диапазон/тип | Смысл |
|---|---|---|
| Источник рейтинга | `clubElo` \| `odds` \| `mixed` \| `manual` | Откуда брать базовую силу атаки/обороны. |
| Веса смешивания | `{ clubElo: 0..1, odds: 0..1 }`, сумма = 1 | Для режима `mixed`. |
| Домашнее преимущество | множитель λ, 1.10–1.25 | Множитель на `lambdaHome` в `models/poisson.ts`. |
| Средняя результативность | голов/матч, обычно 1.2–1.6 | Базовое значение `avgGoals` в `ModelDefaults`. |
| Шум рейтинга σ | 0–0.3 (доля) | Как сейчас `modelDefaults.sigma`, но настраиваемый из UI, а не только из конфига. |
| Поправка на ничьи (ρ Диксона–Коулза) | вкл/выкл, значение ρ | Уже реализовано в движке (`dixonColesTau`), нужен только UI-переключатель. |
| Затухание формы | вес последних N матчей, 0–1 | Экспоненциальное взвешивание последних результатов при пересчёте `attack`/`defense` из сырых данных. |

## Параметры отдельной команды

| Параметр | Тип | Смысл |
|---|---|---|
| Базовый рейтинг Эло | число | Общий рейтинг силы, используется как запасной вариант и для Dota-серий. |
| Рейтинги атаки/обороны | числа | Раздельная сила в нападении/обороне для пуассоновской модели. |
| Ручная корректировка | ±% | Точечная поправка на травмы ключевых игроков, дисквалификации, усиления трансферного окна. |
| Флаг «ротация в последнем туре» | булево | Когда место команды в этапе уже решено и ожидается ротация состава — снижает эффективную силу в оставшихся матчах. |

## Киберспорт (Dota 2)

| Параметр | Тип | Смысл |
|---|---|---|
| Вес LAN vs. онлайн | 0–1 | Результаты на LAN обычно показательнее — выше вес в перерасчёте рейтинга. |
| Сброс рейтинга при смене ростера | вкл/выкл + доля сброса | Частичный откат рейтинга к среднему по региону при значимой замене состава. |
| Увеличенный σ после патча | вкл/выкл + множитель | Временное расширение неопределённости после крупного геймплейного патча, пока новый мета не устоялся. |

## Источники данных (для README и `scripts/update-data.ts`)

Перед реальным подключением любого источника — проверить актуальные условия использования,
лимиты запросов и (для платных/ограниченных API) наличие ключа.

### Футбол — сила команд

- **ClubElo** (`http://api.clubelo.com/YYYY-MM-DD`) — основной источник, бесплатный CSV с
  рейтингами европейских клубов.
- **Коэффициенты букмекеров** через The Odds API (бесплатный тариф с лимитом запросов).
  Коэффициенты переводятся в вероятности с удалением маржи (overround) — лучшая краткосрочная
  оценка, так как в них уже учтены травмы/состав на конкретный матч.
- **Opta Power Rankings** (theanalyst.com) — ориентир для ручной сверки; публичного API нет.
- **Коэффициенты УЕФА** — грубый запасной вариант при недоступности остальных источников.

### Футбол — календарь и результаты

- **football-data.org** — нужно проверить, какие именно еврокубки входят в бесплатный тариф.
- **API-Football**.
- **openfootball** на GitHub (открытые данные, без ключа).

### Dota 2

- **OpenDota API** — `/teams` отдаёт рейтинг команд, `/proMatches` — результаты матчей.
- **STRATZ API** (GraphQL, нужен токен).
- **Liquipedia** — сетка турнира и результаты; обязательно соблюдать их условия использования
  API и лимиты запросов.
- Букмекерские коэффициенты — как и для футбола, ориентир на краткосрочную силу.

## Как это должно подключиться к движку (когда будет готово)

Параметры выше не требуют изменений в `src/engine` — они влияют только на то, какие числа
попадают в `ratings.json` (через будущую версию `scripts/update-data.ts`) и какие значения
`modelDefaults` передаются в `simulate()`. Иными словами: логика настройки силы команд — это
слой над движком, а не часть его контракта, поэтому она безопасно достраивается позже без
переписывания `formats/leaguePhase.ts` или `simulate.ts`.
